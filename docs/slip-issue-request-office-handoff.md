## 画面側が書くもの

表は `TableSlipIssueRequest`（ID `tblfxuQ9I90rGgMYr`、ベース `appwAnJP9OOZ3MVF5`）。1行が受注1件です。

| 欄 | 中身 | 書く人 |
|---|---|---|
| 依頼ID | `sl-` で始まる ID。まとめ依頼の2件目以降は `元の依頼ID.2`、`.3`… | 画面 |
| 受注RecordID | TableJuchu のレコードID（`rec...`） | 画面 |
| 状態 | `依頼済` → `発行中` → `発行済`／`失敗` | 画面は `依頼済` だけ。あとは事務所PC |
| Book / WorkCord / ItemName | 依頼した時点の値（確認用） | 画面 |
| 依頼者 / 社員番号 / 依頼日時 | 押した人と時刻 | 画面 |
| 処理日時 | 発行済／失敗にした時刻 | 事務所PC |
| 伝票ID | 発行した伝票の伝票ID | 事務所PC |
| 処理メモ | 状態を変えた時刻・PC名・プリンタ・失敗の理由。追記していく | 事務所PC |

画面は受注（TableJuchu）と Excel には何も書きません。

### まとめ依頼（2026-11-11 追加）

選んだ受注と同じ伝票に入る受注があれば、画面は一覧を見せて確認を取り、**1回の書き込みで**まとめて行を作ります。

- 選んだ受注の行: 依頼ID は `sl-xxxx` のまま
- 一緒に入れる受注の行: 依頼ID は `sl-xxxx.2`、`sl-xxxx.3`…（最大9行。選んだ受注と合わせて10件まで）
- 依頼日時・依頼者は全部の行で同じ

**依頼ID の「.」より前が同じ行は、1つの依頼です。必ず同じ実行の中で一緒に発行してください。** 別々の回に拾うと、同じ納品先・納品日なのに伝票が分かれます。

画面が「一緒に入れる」と決める条件は、選んだ受注と Book・Kname・DeliPlace・Ndate が同じで、進行社外が `受領伝票発行可能`、伝票ID が空、アーカイブ済でない受注です。これは Airtable の値で見ています。

## 事務所PC側で守ること

1. **依頼された受注だけ発行する。** 対象は依頼の行の 受注RecordID で決めます。納品日の範囲（`--slot` や `--date`）では絞りません。
2. **発行の直前にもう一度確かめる。** 進行社外が `受領伝票発行可能`、伝票ID が空、アーカイブ済でない、の3つ。外れた受注は発行せず、その行を `失敗` にして 処理メモ に理由を書きます（伝票ID が入っていたら「発行済み」）。定時の自動発行と重なっても二重に出さないためです。
3. **先に `発行中` にしてから発行する。** `発行中` にできなかった行は発行しません（次の回にまた拾う）。`発行中` のまま残った行は自動では出し直しません。
4. **1枚にまとめる単位は今までどおり** `group_key`（ブック×顧客×納品先×納品日）で、中身は Excel の S96.5 から読みます。画面のまとめ方は Airtable の値なので、Excel 側の納品先（「荷主:」付きなど）が違えば、1つの依頼が2枚に分かれることがあります。その場合は分かれたまま発行し、各行の 伝票ID にそれぞれの番号を書いてください。
5. **同じ納品先・納品日の保留（`GROUP_HOLD`）は、依頼モードでは掛けない。** まだ工程の途中の受注があることは、画面が「この伝票に入りません」と見せたうえで確認を取っています。
6. **古い依頼は出さない。** `kotei_print_file.py` の `COPY_MAX_AGE_MIN` と同じく、古すぎる `依頼済`（表の説明は2時間）は発行せず `失敗` にします。PCが止まっていた後にまとめて出さないためです。
7. **終わったら行を更新する。** `発行済` なら 処理日時 と 伝票ID、`失敗` なら 処理日時 と 処理メモ の最後の行に理由。画面は 処理メモ の最後の1行を「発行できませんでした：○○」と出します。
8. 伝票ID の採番・Airtable への記録・S96.5 への記録・印刷後の同期は、定時の自動発行と同じ道を通してください（`reserve_ticket_id`、`record_issued`、`sync_airtable_after_print`）。

## 画面が状況をどう出すか

画面は15秒ごとに、その受注の行の 状態 を読みます（最長10分）。

- `依頼済` → 「発行待ち」、`発行中` → 「発行中」
- `発行済` → 「受領伝票を発行しました（時刻・伝票ID）」
- `失敗` → 「発行できませんでした：（処理メモの最後の行）」

`依頼済`・`発行中` の行がある受注は、画面からもう一度依頼できません。行を残したまま止まると、その受注はずっと押せなくなるので、必ず `発行済` か `失敗` に進めてください。

## 動かし始める手順

1. 事務所PCで依頼モードを作り、1分ごとに起動する（`run_kotei_copy_print.bat` と同じ形）。
2. 試験用の受注1件で、依頼 → 発行 → `発行済` と 伝票ID の記録まで確かめる。まとめ依頼（2〜3件）も確かめる。
3. Vercel の環境変数に `SLIP_ISSUE_ENABLED=1` を入れて再デプロイする。これを入れるまで、画面のボタンは依頼の表に何も書きません。
