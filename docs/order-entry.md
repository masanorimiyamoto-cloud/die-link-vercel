# スマホの新規入力

2026-11-12。工程の詳細カードを開かずに、新しい受注を入力する入口を追加。

- 上部の「＋ 新規入力」から開く。`/process.html?mode=new` でも直接開ける。
- 最初に、ログインした本人が最近登録した品目を最大12件表示する。作業ログの本人の「新規受注」直近50件から読み、同じBook・コード・顧客・納品先はまとめる。削除済みの受注はサーバーの候補から除く。
- 同じ端末にも本人別の控えを保存する。候補を選ぶと必ず元の受注を読み直すため、古い顧客・納品先や削除済みの控えのまま登録しない。
- 最近の候補にない品目は、コード・品名・顧客名で検索できる。空白区切りはすべて一致。Bookで絞れる。アーカイブ済みも候補に含め、新しい納期の受注を200件まで読み、同じ品目をまとめる。打ち切りは画面に知らせる。
- 品目を選ぶと数量・納期・連絡事項の入力をすぐ開く。顧客・納品先を表示して確認する。登録後は最近の品目に追加し、続けて入力できる。

既存の受注カードからの「この品目で新規受注」と同じ登録処理を使う。二重登録の確認、保存結果不明時の案内、承認済・Excel取り込み待ちの登録ルールは共通。顧客名の自由入力や「社内半製品用」への切り替え、在庫残数管理、Excel同期処理の変更は含めていない。新しいAirtableフィールドは不要。

## ローカル検証

本番のAirtable・Excel・プリンタは使わない。

```powershell
node tools/process-regression.cjs
node tools/order-entry-regression.cjs
```

画面確認用のモックサーバー:

```powershell
node tools/process-mock-server.mjs 8791
```

`http://127.0.0.1:8791/process.html?mode=new` で架空の品目を表示する。

ChromeがあるWindowsでは、専用の一時プロファイルによる390px幅のブラウザ検証も実行できる。モックの受注・履歴は開始時にリセットする。

```powershell
node tools/order-entry-browser-smoke.cjs http://127.0.0.1:8791
```

最近の品目→直接入力→登録、顧客検索、既存の作業リストへの切り替えを確認し、画面PNGの保存先を表示する。Chromeが別の場所にある場合は`CHROME_PATH`で指定する。
