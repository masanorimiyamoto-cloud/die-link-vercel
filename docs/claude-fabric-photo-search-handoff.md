# Claude Codeへの改修依頼「既存の図面画像から生地を探す」

「知る」の「生地から品番を探す」を改修してください。作業者がスマホで手元の生地を撮ると、すでに受注に登録してある図面画像の中の生地と照合し、同じ生地を使う品番候補をすべて見られるようにしてください。**最優先の受け入れ条件は、`TableFabric` が0件の状態で、見本写真の再アップロードも品番の手入力もせずに検索が成立することです。** 改修に必要ならアプリとAirtableの両方を変更できます。

## 初回実装（5dc8f05）の監査結果

- 実装コミットは `5dc8f05` です。`action=search` は `TableFabric` の有効な行の `見本写真` と `品番` を使います。見本が0件だと `noSamples` で終了し、画面は事務所での手登録を案内します。`TableJuchu` を読むのは候補決定後に品名・進行状況を付ける段階です。 [検索API](../api/material-match.js)・[候補の組み立て](../api/_fabric.js)・[画面](../public/js/scan-spec-google.js)
- 2026年11月18日の監査時点で `TableFabric` は0件でした。`TableJuchu` の納期が新しい100受注のうち82件には `画像` 添付があり、`-zu` 画像を持つ品番は70種類ありました。これは図面の存在を数えた値で、生地が写っている件数は個別に判定する必要があります。 [受注テーブル](https://airtable.com/appwAnJP9OOZ3MVF5/tbl3r511iE8MS22vm)
- 実画像を確認したところ、`Ta / 3688` の `-zu` には赤橙色の地に金色の丸い柄が繰り返す生地が写っていました。`Ta / 2100` の `-zu` は緑色の寸法入りの抜型線画でした。同じ接尾辞が両方に使われています。
- 現行コードには、見本が73種類に達すると検索全体が止まる、見本画像の取得失敗が一部未照合の表示に反映されない、AIの回答を別の呼び出しに送った見本の番号でも受理できる、という問題があります。

## 改修する検索の流れ

1. **受注の画像を自動で検索対象にする。** `skydbss / TableJuchu` の `画像` を全ページたどり、添付元の `Book / WorkCord` と結び付けてください。同じ品番に複数の受注や添付があれば、古い受注にある有用な写真も対象です。Driveにしかない図面を補う場合は、既存の品番指定照合で使っているファイル名とフォルダを参照できます。
2. **図面内の生地が写った部分を比べる。** 現物写真はそのまま、図面の一角に生地見本が貼られていればその部分を使ってください。抜型の形、寸法、余白、ラベルを比較から外し、色・柄・織り目を見ます。線画やシールだけの画像は見本から除きます。ファイル名だけで採否を決めると `Ta / 3688` を取りこぼします。
3. **候補を元の品番までたどる。** 類似する画像を持つ各受注から `Book / WorkCord` を取得します。別途確認済みの生地と品番の対応があれば、独自の写真を持たない品番もそこから加えてください。品番の根拠に使えるのは登録済みの対応と照合対象の画像です。`Material` は補助情報です。例えば `B/C5*C5` は多数の品番で共有されており、文字列の一致だけで同じ生地と判定すると誤った候補が増えます。
4. **作業者には見本と全品番を返す。** 品番やQRの入力前に撮影でき、結果は「この生地を使う品番候補 ○件」として、比較した生地の画像、`Book / WorkCord`、品名を表示します。同じ品番の受注は1件にまとめ、異なる抜型の品番と異なる `Book` は残してください。進行中の品番を優先し、各行から既存の品番検索を開けるようにします。似た別の生地は見本で見分けられるようにし、表示件数の上限で同じ生地の品番を落とさないでください。
5. **件数が増えても現場で使えるようにする。** 毎回全図面をAIに送り直さず、既存画像から自動で検索用の索引を作るなど、候補を絞ってから詳細に照合してください。索引を使う場合は初回の取り込みと、追加・差し替え・削除の反映まで実装します。Airtableの添付URLには期限があるので、永続的な参照にはレコードID・添付IDを使い、表示や再取得時には有効なURLを取得してください。`TableFabric` は確認済みの対応や例外の補正に活用できます。通常の検索で現場に二重登録を求めないでください。
6. **検索できた範囲を正しく伝える。** 画像取得やAI照合が一部失敗した場合は、見つかった候補と「一部未照合」を表示してください。全件失敗・索引準備中・撮影不鮮明・照合を終えて候補0件を区別し、状況に応じて再試行や再撮影を案内します。AIが返した候補IDは、その呼び出しで実際に画像を渡した見本に限定して検証してください。

## 追記　品番ごとに注釈の違う専用図面がある場合

同じ生地を使う品番でも、品番専用の図面があり、注釈の内容や位置、抜型の輪郭が変わります。最初の試作では、各図面を元の品番に結び付けたまま、撮影写真と個別に照合し、該当した全品番を返せば作業者の目的を満たせます。全品番を先に生地別に分類する作業は省けます。

1. **すでにある生地範囲の座標を使う。** 作業ツリーの `api/_fabric.js` は索引に `region` を持ち、`buildSearchParts` が図面全体に「横○〜○％・縦○〜○％」という説明を添えています。まず同じ試験写真で、この方法と、元図の該当部分を実際に切り出して渡す方法を比べてください。注釈が生地の上に重なる場合は、文字や矢印の少ない場所で、柄の繰り返しが一つ見える広さを選びます。必要に応じて別の場所をもう一枚使い、複数の切り出しが一致しても元の品番は一回だけ出します。画像の再登録は不要です。
2. **色と柄が同点の候補をどう扱うか確認する。** 現在の `prefilter` に同じ色・柄の見本を37件渡すと、先頭36件が選ばれ、37件目は画像照合に届きません。末尾に同じ生地の別品番を置いて試してください。例えば、最初の36件を比較したあと、境界で同点だった見本も続きの組として比較できます。続きが残る間は画面にその旨を示してください。色と柄の分類が同じという理由だけで品番を一括追加すると、似た別生地が混ざります。
3. **少数の図面で、注釈と生地のどちらに反応したかを確かめる。** 正解例には「同じ生地で注釈・抜型が違う2品番」、誤候補を見つける例には「注釈・抜型が似ていて生地だけ違う1品番」を用意します。検索には図面と別に撮影した現物写真を一枚使います。前者の2品番が両方出たか、後者が混ざったか、比較に使った切り出しに生地が十分写っていたかを記録してください。実例がまだ揃わなければ、元図の注釈だけを変えたテスト画像で先に確認でき、現物での結果と区別できます。
